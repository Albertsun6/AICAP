# Phase 1 + 1.2 + 1.5：问题界定 + 澄清提问 + Research Brief

> **前提**：进入 Phase 1.5 前必须 Read `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/survey/prompts/brief-template.txt`（见 SKILL.md §Prompt Template Read Gate）。

## Phase 1：问题界定（防止确认偏差，先于搜索）

**做什么**：
1. 将用户输入标准化为一个可评估的研究问题（"如何做X" → "在Y约束下，做X的最佳方案是什么"）
2. 定义 3-5 个评估维度（**必须在搜索前确定**，防止事后根据搜索结果选维度）
   - 常见维度：复杂度 / 性能 / 社区活跃度 / 学习曲线 / 维护成本 / 适用场景
   - 按用户场景定制，不要套通用模板
3. 写出初始假设（你认为哪个方向可能最优，搜索完再对照）

**输出**：研究问题陈述 + 评估维度列表 + 初始假设（内部使用，不展示给用户）

## Phase 1.2：澄清提问 Gate（必要时，多轮，≤3 轮）

> **为什么放在这里**：Brief 一旦冷冻，四路搜索、综合、终审全部对着它跑——**靶子立错，后面全白干**。
> 澄清的唯一窗口在 Brief 冷冻之前；提问的成本（用户几十秒）远低于猜错方向的成本（整轮调研作废）。
> 但零打扰同样是承诺：**没有 blocking unknown 就一个问题都不问**——提问是为了立准靶子，不是免责仪式。

### 触发判据（合取门槛，全部满足才算 blocking unknown → 必须问，不许默默猜）

"答案不同会影响建议"太宽——多数开放调研都缺预算/优先级，按这个标准会次次触发、违背零打扰。
一个未知要**同时满足**以下四条才算 blocking：
① 存在**实质分叉**——提问前必须能写出 `答案 A → 靶子 A / 答案 B → 靶子 B` 的具体分叉，写不出就不问；
② 上下文 / 项目文件 / 对话历史**推不出来**；
③ **没有安全默认或条件化覆盖**——能用"分场景给建议"（如"预算敏感选 X，性能优先选 Y"）兜住的不问，条件化覆盖是默认手段；
④ 猜错会使**本轮研究大面积返工**（不只是措辞差异）。

满足四条的典型：

1. **研究对象有多种合理解读**——"调研 X"里的 X 指代不清（如"调研 agent 记忆方案"：给 Claude Code 用还是给自研产品用？）
2. **评估维度的优先级只有用户知道**——成本 / 性能 / 学习曲线 / 生态哪个优先，上下文推不出来
3. **关键约束缺失且会改变结论**——预算、平台、团队技能栈、现有依赖、合规要求
4. **排除范围不明**——"比较 X 和 Y"时，是否允许最终推荐 Z？

**档位类未知不单独成轮**：重要度档位（重大决策五路 vs 常规四路）或产物档位（A/B/C）拿不准时，
**并入**已触发的提问轮顺带问；若本轮没有其他触发项，直接走默认（常规四路 / B 档），不为档位单独打扰用户。

### 不问判据（防滥用，同样硬）

- 上下文 / 项目文件 / 对话历史能推断的 → 自己推断，写进 Brief「初始假设」显式记录
- 常规默认能覆盖的（信源约束、成功标准数值）→ 走默认
- 与最终建议无关的细节 → 不问
- 自检："这个问题的答案，是不是**只有用户知道 / 只有用户有权定**？" 不是 → 不问

### 轮次协议

- **维护显式未知队列**：识别出的 blocking unknown 全部入队，按"猜错的返工影响"排序
- **每轮攒齐再问**：从队列取最多 4 个合并成**一次** AskUserQuestion（每问给 2-4 个具体选项；**有项目证据支撑才标推荐项**，纯偏好题不伪造推荐——可给"无固定优先级，分场景比较"类中性选项，否则 agent 是在替用户锚定偏好），不碎片化打断
- **进入下一轮的条件**：队列里还存在**未问**（上轮容量超限溢出）或**新产生**（上轮答案引出，如用户选"要跨平台" → "哪些平台？"）的 blocking unknown。队列空 → 停，进 Phase 1.5
- **上限 3 轮**：到限即停
- **任何终止路径**（队列清空以外的：3 轮到限 / 用户未答 / 降级）都必须把队列剩余未知转成 Brief「初始假设」显式记录，并在报告 §调研 metadata 标注"以下假设未经用户确认"——不许静默丢弃
- **轮与轮之间不做任何搜索**——先立靶再开枪，澄清是问题界定的一部分

### 答案冷冻

- 所有 Q/A 写入 Brief 的「用户澄清记录」字段（模板见 prompts/brief-template.txt），随 Brief 全文注入 Phase 2 各 agent prompt 与 Phase 6 终审 prompt——下游 agent 必须知道哪些边界是用户亲口定的，不许推翻
- 用户未答或答"你定"的问题 → 转成显式假设进「初始假设」，**不算**用户确认

### 降级（非交互 / 用户不响应，不阻塞）

- **判定依据（可观测的，不许凭感觉猜"用户大概不在"）**：AskUserQuestion 不在当前可用工具列表、
  或调用返回错误/拒绝（非交互 / SDK / 自动化环境），或用户已明说"别问，直接跑"
- 降级时：所有 blocking unknown 全部转成显式假设写进 Brief「初始假设」，报告 §调研 metadata 加一行
  `澄清: 未执行（<原因>），基于假设: <列表>`——让用户读报告时一眼看到靶子是怎么立的
- **部分回答**：工具返回但某些问题未选/答"你定" → 已答的照常冷冻进「用户澄清记录」，
  未答的按"未答"转「初始假设」，不算用户确认（见 §答案冷冻）
- **Phase 1.2 只能由主 agent 执行**——subagent 没有 AskUserQuestion 工具，不许把澄清外包给 subagent

## Phase 1.5：Research Brief（**foundational**，所有下游 agent 对照）

> **原则**：Phase 1（+ 必要时 1.2 澄清）后产出一份冷冻 Brief，作为 north star。Phase 2 四路 agent、Phase 2.5 反射 gate、Phase 5 综合、Phase 6 终审全部对照 Brief 验收——消除"各路 agent 跑歪不在同一靶子上"的最大失败模式。

**Brief 模板路径**：`${CLAUDE_CONFIG_DIR:-$HOME/.claude}/skills/survey/prompts/brief-template.txt`（Read gate 见 SKILL.md §Prompt Template Read Gate）

按当前研究填字段，内存中持有作为 north star；Phase 2 给 **Agent A/B 与 X1/X2 全部四路**的 prompt prefix 强制注入 Brief **全文**（含用户澄清记录与初始假设——澄清只到半数搜索路等于没澄清）；Phase 6 终审 prompt 也注入作为对照标准。

**Brief 必含字段（invariants）**：
- **研究问题** / **评估维度（3-5）** / **子问题清单** / **排除范围** / **用户澄清记录**（Phase 1.2 的 Q/A；未触发则写明）/ **初始假设**（未经用户确认的，含来源标注）
- **成功标准**：默认 ≥8 source、近 12 月源 ≥30%、primary source 占比 ≥40%
- **信源约束**：`allowed_domains` / `blocked_domains`（默认含中文社区 baseline）/ `source_freshness` / `source_connectors`（MCP 占位）

### Trusted Source Scope（#7）何时升 P0

当 /survey 扩展到以下任一场景，**Trusted Source Scope 必须升为强制字段**而非可选：
- 私有文档 / 内部知识库调研
- 指定站点 allowlist 模式（如仅 gov / edu / 内部 wiki）
- 启用 MCP source connectors（Google Drive / Gmail / GitHub / Slack / Microsoft 365 类）
- source freshness 严格要求（金融 / 医疗 / 安全场景）

当前默认仍是 P1（开放 Web 调研可选填）。

# 阶段 4：灰框线框

**本阶段只回答**：每一屏放哪些东西，谁更重要，布局撑不撑得住流程里的步骤。
**本阶段不谈**：颜色、字体、图标风格、真实数据、数据从哪个接口来、参考了哪个软件。

## 入口

- 流程图已经过关（阶段 3）；阶段 3 被裁掉时，按裁剪表用任务清单自己拆步骤。
- 处理前面留下的「留待阶段 4」条目。
- 先看同类成熟软件里同类页面的布局（列表加详情、三栏、向导……），记进借鉴记录。信息密集的页面可以读 NN/g 关于数据表格（https://www.nngroup.com/articles/data-tables/）和空状态（https://www.nngroup.com/articles/empty-state-interface-design/）的文章。

## 交付物：灰框线框

一个页面一帧，按流程分批出，不要一次把所有页面全画完。先画被多个任务共用的页面。每批三到五页，过了关口再画下一批。这样用户每次要看的东西少，前一批的意见也能用到后一批。

**线框里可以有的**
- 灰色的框、线和文字，只用灰阶。
- 真实的导航项和页面标题，名字取自站点地图。
- 区块的名称（「待处理列表」「详情」），占位的内容（灰条、「标题文字」）。
- 表示主次的手段：大小、位置、粗细、灰度深浅。
- 主要操作按钮的文字（「批准」「新建」）。

**线框里不能有的**
- 任何彩色，包括状态色和品牌色。
- 真实数据、数据来源或接口名、实现说明。
- 「借鉴某某」的标注。
- 大段解释这块区域是干什么的文字。区块需要一段话才说得清，说明名字起得不好或者塞了太多东西。

这些东西不是没用，是不属于这一关：数据来源记进「留待阶段 5」，借鉴留在借鉴记录，说明写在阶段文档里。

### 放在哪里

**Figma 可用时**：线框放 Figma 的设计文件（不是 FigJam），阶段文档里放链接。
- 动手前先用 Figma MCP 的 skill 读取工具，现读写画布的基础 skill，照它当前的结构要求做。读不到时告诉用户，退到仓库方式。
- **有一处有意偏离官方做法**：官方的页面生成做法若要求先搜索设计系统并绑定它的颜色变量和组件，本阶段不照做，只用灰阶填充。那是为高保真准备的；绑定变量会把颜色和成品组件带进线框，评审就会滑向视觉。在给用户的说明里写一句这个偏离。
- 把文件链接给用户，请他们直接在图上评论。用评论读取工具读回未解决的评论，改完在对话里给对照表：哪条评论 → 改了什么（或为什么不改）。评论只能由用户自己标为已解决。

**Figma 不可用时**：每页一个灰框 HTML 文件（或一个文件里一页一节），只用灰阶，放交付物目录里，评审在对话或 PR 评论里做。

## 机械自检

交给评审之前先查，出稿人自己说「没混层」不算数：

- **只有灰阶**：Figma 里读回每帧所有节点的填充色和描边色，红绿蓝三个分量必须相等。HTML 里搜十六进制、rgb、hsl 写法和颜色名，同样要求三个分量相等，并且不用链接的默认样式（默认是蓝色）。不合要求的一律改掉。
- **没有越界的字**：线框的文字里不出现接口名、数据来源、「借鉴」「参考」字样。

## 评审

两种方法各查一类问题，记录格式见 `references/review-methods.md`，先读它。

**一、认知走查**（查「照着流程走得通吗」）
拿阶段 3 的流程图，一步一步在线框上走。每一步问四个问题：
1. 用户此刻会想要做这件事吗？
2. 用户看得到做这件事的入口吗？
3. 用户能把这个入口和想做的事对上吗？
4. 做完之后，看得出来事情有了进展吗？

任何一问答「否」，这一步就算失败。只记失败的步骤：哪一步、哪一问、为什么。

两点说明：
- 第 4 问在灰框上按「操作之后有没有去向」来答：有下一屏、结果区块或状态的占位就算有。反馈的细节灰框画不出来，记入「留待阶段 5」，不算失败。
- 分批时，每批只走落在本批页面上的步骤。落在还没画的页面上的步骤记为「未覆盖」，不算失败。最后一批过关前，把每条核心任务从头到尾完整走一遍，这时不允许再有「未覆盖」。

**二、启发式评估**（查「页面本身有没有通病」）
静态的灰框能评的是下面几条，其余几条（系统状态是否可见、出错后能否恢复、帮助文档）留到高保真阶段：
- 用词贴近用户的说法，不用内部术语
- 一致：同类东西在各页的位置、叫法相同
- 让用户认出来，而不是靠回忆：需要的信息就在眼前，不用记着上一页的内容
- 简约：每屏只放这一步需要的东西
- 用户能退出、能返回
- 熟手有捷径（批量操作、键盘、搜索）
- 防止出错：危险操作和常用操作隔开，结构上不容易点错

每个问题按 0–4 定严重度：0 不是问题，1 只是观感，2 小问题，3 大问题，4 必须先解决。

**预筛**：派一个没参与出稿的子代理，给它线框（截图或文件）、站点地图和流程图（阶段 3 被裁时给任务清单和你拆好的步骤），做上面两种评审。让它详细报严重度 3 和 4 的问题以及走查失败的步骤；严重度 2 的只报条数和每条一行标题，附在最后供用户抽看。

**给用户的关口汇总**：这批画了哪几页；走查失败的步骤和未覆盖的步骤；严重度 3、4 的问题；未解决的评论及对照表；越界意见已挪到哪里；请用户决定过、改、还是回退到前面的阶段。

**判定**：过关 = 没有走查失败的步骤、没有严重度 3、4 的问题（两者都允许用户明确接受并记入未决项），每条未解决的评论都有对应的改动或用户同意搁置，机械自检通过，未执行的评审有用户自己走的结果或用户明确同意不做，用户确认。

## 出口

全部批次过关后，在阶段文档的「下一阶段的输入」里写：每页由哪些区块组成，每个区块的用途一句话，哪些交互在灰框里表达不了、要在高保真阶段验证。

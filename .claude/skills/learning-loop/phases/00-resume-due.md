# Phase 0 — 会话开始 / 续做到期复习

> **每次**调用 learning-loop **都先跑这个**。这就是整个"无 app 调度器"。证据:间隔效应(Cepeda 2006)+ 交错(Rohrer 2020)。

## 步骤
1. **取今天**:跑 `date +%F`(或 `bash scripts/due.sh <VAULT>`)拿到 ISO-8601 的今天。**绝不**用模型时钟/训练截止猜。bash 不可用 → **问用户**今天日期。
2. **定位库**:`$LEARNING_VAULT` → 调用参数 → 默认 `<cwd>/learning-vault/`。库不存在且用户要学新东西 → 进 Phase 1(首次会创建);用户是来复习的却没库 → 报"还没有笔记库",别假装有。
3. **扫描**:glob 库里所有 `.md`,读各自 frontmatter 的 `next_review`。`scripts/due.sh` 已封装(并自动探测 GNU/BSD date、坏日期大声报错)。
4. **建到期队列** = `next_review <= 今天` 的笔记;排序 `(next_review 升序, lapses 降序)` —— 最逾期/最 leech 的先出。
5. **交错**:把队列**按主题/tag 打散**(绝不让一个主题连续刷完)——强制类型辨别(Rohrer 2020)。
6. **限批**:默认每次最多 **20** 张,其余顺延。
7. **报横幅**:`今日到期: N 张`。坏日期/缺目录 → **大声报错并停**,绝不静默跳过。
8. **交给 Phase 4** 测验(日常复习路径 `0 → 4 → 5`)。
9. 若**无到期**且用户想学新东西 → 进 Phase 1。`state=leech` 的卡**不进**正常队列(见 scheduler.md)。

## 不许
- 不许凭"我觉得今天是…"算日期。
- 不许把坏 frontmatter 的卡悄悄丢掉(会让用户以为没到期)。
- 不许跳过复习直接学新——除非确实没有到期卡。

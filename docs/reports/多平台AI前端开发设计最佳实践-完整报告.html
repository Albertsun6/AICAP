冲突分析

冲突 1：流式 UI — 技术优化 vs UX 悖论

技术视角认为 RAF Batching 能解决流式 UX 问题；社区视角发现原始流式渲染本身是 UX 反模式——强制自动滚动让用户感知比批量交付更慢。

裁决：技术优化是必要条件，但不充分。还需设计层主动处理：60px 阈值意图检测、布局锚定、流式进度指示器。

冲突 2：跨平台策略 — 无普适答案

三路 Agent 立场分散：设计 Token 统一视觉、原生 SDK、跨平台框架各有支持者。

裁决：交互模型必须原生实现；视觉 Token 可统一；取决于团队规模和产品阶段。

冲突 3：状态管理层叠复杂度

Vercel AI SDK 5 Agentic Loop Control 与 XState 在多步 Agent 场景有概念重叠。

裁决：职责分离——Vercel AI SDK 5 管 LLM 通信，XState 仅用于确定性多步编排（≥5 状态转移时引入）。

流式 UX 设计规则
  • 自动滚动：检测 60px 阈值判断用户是否在主动向上滚，暂停 auto-scroll；用户回底部时恢复
  • Markdown 渲染：块级 React.memo memoization + 50ms 节流；在空白/句边界触发解析，避免全量重解析
  • 代码块：等待闭合围栏后渲染，或显示流式进度指示器
  • 无障碍：role="log" + aria-live="polite" + aria-atomic="false"（95%+ 覆盖率）
    未来增强：Edge 136+ ariaNotify() API（当前覆盖率 ~5-10%，不进主推荐）

Web 层推荐

首选：Vercel AI SDK 5 + assistant-ui + Zustand + TanStack Virtual 前提: Next.js + Vercel 部署

若自托管（AWS/GCP），改用 TanStack Query + 自定义 SSE hook（无厂商锁定）或 LangChain.js streaming（backend 已用 LangChain）。

React 18 渲染：RAF Batching + startTransition + TanStack Virtual（消息 100+ 条时）
React 19 渲染：useOptimistic + streaming Suspense（可简化 RAF 手动实现）
MCP tool call 渲染：XState 建模 tool call 的 Pending/Executing/Success/Error 四态

iOS 层推荐

条件推荐路径关键 API
iOS 26+，隐私敏感，离线需求 Apple Foundation Models streamResponse，结构化 Swift 类型流式快照
iOS 18+ 兼容，云端，快速上线 GetStream stream-chat-swift-ai StreamingMessageView（5ms 字符级队列）
最大兼容性 / 完全自定义 URLSession SSE + 自定义渲染 iOS 16+，Text Renderer API（iOS 18+）
⚠️ Apple Foundation Models 仅支持 ~3B 规模模型。复杂推理场景需结合云端 API 或采用路径 B/C。

Android 层推荐

条件推荐路径关键组件
Android 15+，设备端，Google 生态 Gemini Nano / AICore API Developer Preview（需申请访问权限）
主流场景，Android 8+ GetStream Compose AI StreamingText + AITypingIndicator，OkHttp EventSource
完全离线 / 隐私极敏感 llama.cpp + ARM NEON/SVE 维护成本高，速度受硬件限制

跨平台策略推荐

推荐：设计 Token 统一 + 平台原生渲染层
① SSOT：Figma Variables 作为设计 Token 单一事实来源
② Transform pipeline：Style Dictionary 或 Tokens Studio 将 Token JSON 转换为 iOS ColorSet/SwiftUI → Android Material You Theme → Web CSS 变量/Tailwind
③ 渲染层：各平台使用原生框架，不强行统一交互模型
可接受折中：React Native + Expo（中小团队，Web 优先）。需为 Apple FM 和 Gemini Nano 分别编写 Native Module。
不推荐：强行用 React Native/Flutter 统一三平台交互（iOS 手势体系和 Android 导航范式无法原生表达）。
